## Rastreo e indexabilidad

**H-004 — Referencia de sitemap y pruebas pendientes de contraste público.** El archivo local `docs/robots.txt` apunta a `/docs/sitemap.xml`, aunque `site_url` declara la raíz; las pruebas SEO usan también `/docs/` (E-013). Esa divergencia justifica comprobar qué robots se sirve, si el sitemap declarado responde y qué URLs contiene. No permite concluir que exista un problema de producción ni de indexación.

**H-005 — Navegación observada en copia de caché.** Una copia extraída de la portada muestra enlaces de navegación a las cuatro categorías y una copia de Data Mesh muestra el contenido (E-014); esto no confirma que la galería funcione sin JavaScript ni que todas las páginas sean rastreables. El acceso directo falló por proxy y el extractor no pudo recuperar varias páginas de la muestra (E-015, E-016). La indexabilidad no demuestra indexación.

**H-006 — El servidor de desarrollo ofrece páginas y metadatos en la muestra.** El propietario facilitó `http://127.0.0.1:8000/`. En ese entorno la portada, About, un notebook, un proyecto, una referencia y el recurso Data Mesh en EN y ES responden 200, y una URL inventada responde 404. Las páginas muestreadas incluyen título, descripción, canonical, alternates y JSON-LD (E-018). Sus canonical apuntan al host de desarrollo, comportamiento que no acredita qué se genera o sirve en producción. Los alternates no se validaron integralmente y la descripción de la muestra ES aparece en inglés.

**H-007 — Discrepancia reproducida en desarrollo.** El robots local declara el sitemap público bajo `/docs/`, pero el servidor de desarrollo sirve `/sitemap.xml` y responde 404 a `/docs/sitemap.xml` (E-019). El destino declarado es de producción: debe comprobarse allí antes de afirmar que está roto o implementar un cambio.

**H-008 — Galería y navegación tienen mecanismos distintos.** El HTML inicial contiene enlaces de navegación a categorías, mientras el contenedor de galería llega vacío y la plantilla carga su contenido con JavaScript desde el JSON de publicaciones (E-020). El navegador automatizado no pudo iniciarse por restricciones del entorno; sigue pendiente comprobar el contenido renderizado. Esto no prueba qué enlaces Google descubre ni si indexa las páginas.

**Pendiente de comprobación reproducible en producción:** registrar status y cada `Location` de HTTP/HTTPS con y sin www; comparar `/`, `/docs/`, robots y ambos sitemaps; muestrear About, referencia, proyecto, recurso, notebook, par EN/ES y URL inexistente. Guardar canonical, hreflang, noindex, título, descripción y JSON-LD del HTML de cada respuesta, además de comprobar navegación y galería con y sin JavaScript. Las pruebas locales existentes no cubren la mayoría de estos puntos (E-013); la ausencia de MkDocs en el intérprete actual impidió construir localmente (E-015). La herramienta de lectura no proporciona HTML completo ni códigos HTTP, por lo que sería incorrecto marcar esa parte como superada.

## Analítica y observabilidad

**H-012 — Etiqueta configurada, recepción desconocida.** `mkdocs.yml` declara el identificador de medición `G-T0L50BG8T6`. La portada del servidor local facilitado por el propietario contiene un script `__analytics` que prepara ese identificador, crea dinámicamente el script de Google y se invoca desde el HTML (E-028). La prueba E2E existente solo busca el script o el marcador. No se observó una implementación de consentimiento en la búsqueda acotada del repositorio ni un marcador de consentimiento en el HTML local; esto no demuestra el comportamiento completo de consentimiento en producción. El HTML estático no ejecuta JavaScript y no demuestra que la biblioteca se descargue, que se envíe una solicitud ni que una propiedad reciba datos. El navegador automatizado quedó bloqueado (E-020) y la producción no pudo inspeccionarse por HTTP directo. El 404 al acceder a Analytics comunicado por el propietario (E-006) tiene causa desconocida.

**Decisión — intentar recuperar antes de crear.** Una propiedad existente podría conservar datos históricos y evitar duplicaciones; una propiedad nueva permitiría empezar una medición cuando no sea viable recuperar la anterior, pero tendrá una línea de base nueva y no recuperará por sí sola los datos previos. Mantener el ID configurado hasta saber a qué flujo pertenece; no asumir que exista una cuenta accesible ni cambiarlo durante esta investigación. Si recuperación y verificación resultan imposibles, valorar una propiedad y flujo web nuevos usando la [guía oficial de configuración](https://support.google.com/analytics/answer/14183469?hl=en) (E-030).

Registrar solo si encuentra una propiedad y si un flujo web tiene el ID configurado, sin compartir credenciales ni datos privados. Si hay otro administrador conocido, pedir acceso. Si no queda ningún administrador y se cumplen los requisitos de propiedad, seguir la [recuperación oficial](https://support.google.com/analytics/answer/15191460?hl=en): exige prueba de titularidad de todos los sitios identificados y del identificador de cuenta o todos los IDs de medición; puede requerir información adicional si existen productos vinculados.
