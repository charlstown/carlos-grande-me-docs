# Plan — Add ES/EN language toggle for post content

## Enfoque

La feature combina integración de plugin (build) y un componente cliente propio, así que el riesgo mayor —que `mkdocs-static-i18n` rompa el build o cambie las URLs de los 47 posts existentes— se aborda primero y de forma aislada: se integra y pinea el plugin en `mkdocs.yml`/`requirements.txt`, se valida con `mkdocs build --strict` y solo entonces se construye el resto sobre URLs estables. La decisión de visibilidad del toggle se resuelve en build (Jinja leyendo los alternates que expone el plugin en `page.alternates`) e inyecta data-attributes en el DOM; el JS de cliente —detección por `navigator.language`/localStorage, redirección sin flicker y toggle— sigue el patrón ESM ya establecido por `ReadingProgress` (clase con `mount`/`destroy`, entry con `try/catch` y guard de página), de modo que es testeable con la infra Vitest/jsdom y Playwright existente. El post piloto y los tests cierran el flujo end-to-end al final, cuando el mecanismo ya está en verde.

## Batch 3 — Componente JS del toggle y detección de idioma

- [ ] · @code-developer - Crear `docs/assets/javascripts/components/LanguageToggle.js` como clase ESM con export nombrado y default, siguiendo el patrón de `ReadingProgress.js`. Métodos: `constructor({ toggleSelector = '.md-lang-toggle', storageKey = 'preferred-lang' } = {})`; `static normalizeLocale(navLang)` → devuelve `'es'` si `navLang` (string) hace match con `/^es(\b|-|_|$)/i` (cubre `es`, `es-ES`, `es-MX`, `es-AR`, `es-419`), si no `'en'`; `static getStoredPreference()` → lee `localStorage[storageKey]`, devuelve `'es'`/`'en'` o `null` si ausente/valor inválido, con `try/catch` que devuelve `null` si localStorage no está disponible; `static resolveDefault({ stored, navLang })` → precedencia `stored → normalizeLocale(navLang) → 'en'`; `mount()` → busca el botón `toggleSelector`, si no existe hace `return` (post sin alternate); lee `data-lang-en-url`/`data-lang-es-url`/`data-lang-current`, registra el handler de click; `_onClick()` → calcula el idioma destino (el contrario al actual), guarda la preferencia global en `localStorage[storageKey]` con `try/catch`, y navega con `location.assign(targetUrl)`; `destroy()` → quita el listener. Sin dependencias externas.
- [ ] · @code-developer - Crear `docs/assets/javascripts/components/LanguageRedirect.js` como función/clase ESM con export nombrado y default que implementa la redirección por defecto SIN flicker. Export `applyLanguageRedirect({ toggleSelector = '.md-lang-toggle', storageKey = 'preferred-lang' } = {})`: solo actúa si existe el botón toggle (la página tiene ambas versiones); lee `data-lang-current` y `data-lang-es-url`; resuelve el idioma deseado con la misma precedencia `localStorage → navigator.language (es* → es) → en`; si el deseado es `es`, el actual es `en` y existe `data-lang-es-url`, llama `location.replace(esUrl)` (replace, no assign, para no romper el historial); en cualquier otro caso no hace nada. Guarda de crawler: si `navigator.webdriver` es true o el user-agent contiene `bot|crawl|spider` (regex `/(bot|crawl|spider)/i`), NO redirige (respeta la URL canónica del idioma por defecto). Reutilizar `LanguageToggle.normalizeLocale`/`getStoredPreference` importándolas para no duplicar lógica.
- [ ] · @code-developer - Crear el entry `docs/assets/javascripts/language_toggle.js` (ESM, patrón de `reading_progress.js`): importa `applyLanguageRedirect` y `LanguageToggle`; en una función `init()` envuelta en `try/catch` que loguea `console.error('LanguageToggle failed to initialize:', error)`, primero llama `applyLanguageRedirect({})` (si redirige, el resto no importa) y luego instancia `new LanguageToggle({}).mount()`; arranca con el patrón `document.readyState === 'loading' ? addEventListener('DOMContentLoaded', init) : init()`.
